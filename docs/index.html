Documentation

Using toast-queue

A quick reference to get started. For the full API (options, per-toast config, and every method), see API.md.

Install

Install the library via npm.

npm install toast-queue

Usage

Create a ToastQueue instance. This is where all your toasts render.

import ToastQueue from 'toast-queue' const tq = new ToastQueue();

Then trigger a toast from anywhere using the instance.

<button onclick="tq.add('Toast message...');">Trigger toast</button>

Presets

toast-queue ships unstyled by default, you own every pixel. Two optional presets are included if you'd rather start from a look and adjust from there: minimal, a simple vertical list, and stacked, a card-stack "peek" effect where toasts beyond visibleLimit collapse behind the topmost one.

import 'toast-queue/presets/minimal.css'; // or import 'toast-queue/presets/stacked.css';

Both are plain CSS layered under @layer toast-queue, so your own styles win by default. Treat them as a starting point, not a lock-in.

Options

Configuration passed to the ToastQueue constructor:

new ToastQueue({ root: document.body, // Container element for the toast queue duration: 6000, // Auto-dismiss duration in ms (0 disables it) placement: 'top-end', // 'top-start' | 'top-center' | 'top-end' | 'bottom-start' | 'bottom-center' | 'bottom-end' visibleLimit: 3, // Toasts rendered before the rest are flagged hidden template: { root, item, actionButton }, // Override the default markup });

placement and visibleLimit are also live setters (toastQueue.placement = 'bottom-center') and update everything in place. Per-toast options are passed as the second argument to .add(). See API.md for the full list (dismissible, priority, icon, action, onClose, etc.).

Browser support

toast-queue uses modern, progressively-enhanced browser features, Popover API, View Transitions API, and ariaNotify(), and falls back gracefully where a browser doesn't yet support them (toasts still render and function without animation, just without a transition).

ariaNotify() is the one exception worth calling out: it's how toasts are announced to screen readers. Without it, screen reader users on browsers that haven't shipped it yet won't hear an announcement when a toast appears. If that matters for your app, install the polyfill and load it conditionally so browsers with native support skip it entirely.

npm install @github/arianotify-polyfill if (typeof HTMLElement.prototype.ariaNotify !== 'function') { await import('@github/arianotify-polyfill'); } const tq = new ToastQueue();
