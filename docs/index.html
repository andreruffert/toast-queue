Accessible toast notifications

Try toast-queue in the browser. Tiny, unstyled, framework-agnostic, and built on modern web APIs with progressive enhancement and graceful fallbacks.

Queue controls

Change the placement, and number of visible toasts. Toasts pause while hovered or focused. Pause freezes the entire queue.

0 active

Additional toasts remain queued until space becomes available.

Unstyled by design. toast-queue provides the behavior and accessibility primitives, you provide the look. Optional CSS presets are included if you want a starting point.

Using toast-queue

Get started in a few lines, then customize the queue to fit your app. For the complete API, including options, per-toast configuration, and methods, see the API reference.

Install

Install toast-queue from npm.

npm install toast-queue Copy code

Quick start

Create a ToastQueue instance.

import ToastQueue from 'toast-queue'; const toastQueue = new ToastQueue(); Copy code

Add a toast whenever you need one:

toastQueue.add('Toast message...'); toastQueue.add({ title: 'Changes saved', description: 'Your profile has been updated.', }); toastQueue.add( { title: 'Update available', description: 'A new version is ready to install.', }, { action: { label: 'Reload', onClick: () => location.reload(), }, }, ); Copy code

Styling

`toast-queue` ships unstyled by default, you own every pixel. If you'd rather start from a look and adjust from there, two optional presets are included.

/* core */ import "toast-queue/toast-queue.css"; Copy code

Presets

/* minimal */ import "toast-queue/presets/minimal.css"; /* stacked */ import "toast-queue/presets/stacked.css"; Copy code
  • minimal: a simple vertical list.
  • stacked: a card-stack "peek" effect, where toasts beyond `visibleLimit` collapse behind the topmost one.

Both are plain CSS layered under @layer toast-queue, so your own styles win by default. Treat them as a starting point, not a lock-in.

Configuration

Queue options

Configuration passed to the ToastQueue constructor:

new ToastQueue({ root: document.body, // Container element for the toast queue duration: 6000, // Auto-dismiss duration in ms (0 disables it) placement: 'top-end', // 'top-start' | 'top-center' | 'top-end' | 'bottom-start' | 'bottom-center' | 'bottom-end' visibleLimit: 3, // Toasts rendered before the rest are flagged hidden template: { root, item, actionButton }, // Override the default markup }); Copy code

placement and visibleLimit are also live setters (toastQueue.placement = 'bottom-center') and update everything in place.

Toast options

Per-toast options are passed as the second argument to .add(). See API reference for the full list.

Browser support

toast-queue uses modern, progressively-enhanced browser features, Popover API, View Transitions API, and ariaNotify(), and falls back gracefully where a browser doesn't yet support them (toasts still render and function without animation, just without a transition).

ariaNotify() provides the screen-reader announcement for newly created toasts. Browsers without native support can use a polyfill. Install the polyfill and load it conditionally so browsers with native support skip it entirely.

npm install @github/arianotify-polyfill Copy code
if (typeof HTMLElement.prototype.ariaNotify !== 'function') { await import('@github/arianotify-polyfill'); } const toastQueue = new ToastQueue(); Copy code
